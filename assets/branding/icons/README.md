# EffectStrike product icon exports

Direct size/container exports of the existing approved `../EffectStrike-logo.png`, not new artwork. Original PNG, paired SVG, upstream app icons and upstream favicon are preserved.

## Reproduce/check
- `cargo xtask product-icons --write` generates 20 files: direct Lanczos3 PNG resizes, a nine-size ICO using the existing packer, the macOS iconset, and an unchanged paired SVG for scalable consumers.
- `cargo xtask product-icons --check` verifies generated bytes exactly.
- `python3 scripts/check_product_icon_resources.py` checks source/export hashes and ICO payload sizes.
- `cargo test -p xtask` covers pixel preservation, malformed inputs, ICO entries, iconset verification and actual web icon staging/cache versioning.
- `python3 scripts/check_product_icon_routes.py` verifies native/package/web routing without changing IDs or installer scope.

The native 1024 iconset member retains master PNG bytes exactly. No additional padding, recoloring or geometric redesign; exports preserve the accepted transparent canvas.

## Native ICNS gate — pending in source-only phase

`EffectStrike.icns` is not fabricated on Linux. The standard macOS job uses native `iconutil` to produce it, roundtrip it to an iconset, and verify all ten decoded PNGs against approved pixels. Source head, SHA256 and ICNS are retained as an artifact.

That artifact must be reviewed, copied unchanged here, indexed/attributed and added to the provenance manifest in this same PR before package completion/merge. The separate final-completeness step deliberately fails until the committed ICNS exists in its manifest. Artifact upload happens before this final gate so source-stage export evidence remains available. Once present, the job roundtrips and checks the committed file too.

## Scope and acceptance

Packaging consumers retain executable filenames, application IDs, macOS bundle names, registry keys and installer scope. Existing EffectCraft metadata/copy is not renamed in an artwork-only patch.

Windows CI verifies every icon resource in the actual native executable against the ICO using data-file resource APIs, without executing another binary. Linux tests native decoding and AppImage entry preservation. Web cache identity already hashes changed file contents.

These checks do not prove visible taskbar/Dock/Finder icons, actual installed MSI/AppImage/Flatpak behavior, native FreeBSD/macOS interaction, release signing/notarization, or full-app/GPU correctness. No release or user-machine installation is performed.
